# Project Requirements, Constraints, and Goals
## Project Rationale and Goals
This project was made to develop the contributors' skills in applied Embedded Systems and Firmware engineering. As an amateur project, this should build the foundation needed for engineers in the field. These skills include electronics designing, firmware development, and collaboration between different fields that works alongside the two. <br/>
<br/>
Besides the skills needed for the career, other essential skills for the industry's culture and lifestyle would be built on. Skills such as documentation and version control must be developed.<br/>
<br/>
By the end of the project's life cycle, it shall serve as a portfolio entry for the contributors involved. Further development of the project, such as future version releases, can be done. However, for the first version of the project, only the primary contributors shall work on it. <br/>
<br/>

## Requirements
### General
Besides the product-specific requirements, other requirements concerning the development of the whole project are:
1. Document each milestone or major developement of the project.
2. Use version control regardless of field or discipline of the development, use Git.
3. Proceed to the next development step only after validating the current.
4. Adopt a documentation and version control convention to ensure clear and consistent development.
<br/>

### Products
The project consists of two products. They would be described as "<strong>hanging bot</strong>" for the bot that controls the curtain and "<strong>smart switch</strong>" for the product that controls the hanging bot. The following requirements are:
1. The weight of the hanging bot must be considerably light enough to traverse while pulling and pushing a curtain on a metal railing.
2. The hanging bot must be powered by a rechargeable power source, not single-use power sources.
3. The hanging bot must be able to wirelessly communicate with the smart switch.
4. The smart switch must be able to wirelessly communicate with the hanging bot to command it.
5. If possible, program in bare-metal within feasible means, use the microcontroller's vendor's HAL if bare metal is too tedious or counterproductive. Don't use an Arduino framework for the final products. <br/>

No technical specifics are required, exploration is encouraged.

## Constraints
As this project is developed and managed by students, most likely only one for most of the projects life cycle, the project would be constrained by finances and time. For the sake of minimizing costs for production, the use of breakout boards and modules would be implemented into the products. Creating and fabricating custom made PCBs for the products would be too costly for the contributors. The time it takes to develop the project would also bleed into the time of the contributors, considering that they are still students.
